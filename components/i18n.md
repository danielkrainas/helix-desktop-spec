# Languages and locale formats

Everything Helix itself shows (the shell, the lock screen, the system
dialogs the shell draws, the portals' own dialogs and the login screen)
is translatable and follows a locale for its text, names and formats.
Applications are translated by their own toolkits and catalogues; this
document covers Helix's components only (Helix's applications follow the
same scheme in helixdesktop/apps).

## Catalogue

*GNOME does not document this; Helix's choice:* the components share one
gettext domain, `helix-desktop`, installed as
`/usr/share/locale/<lang>/LC_MESSAGES/helix-desktop.mo`, so a string used
by several of them ("Cancel", "Power Off") is translated once. The
template is `po/helix-desktop.pot` in helixdesktop/desktop; `po/LINGUAS` lists
the languages that have a translation (`po/<lang>.po`), and the
repository's `TRANSLATING.md` is the workflow for adding one. The
`helix-desktop` package installs the compiled catalogues; the
`helix-greeter` package depends on it at the same version and reads the
same catalogue.

- Plurals use the language's `Plural-Forms` (gettext `ngettext`): counts
  of windows, notifications, unread items, minutes and hours.
- Messages that hold values name their placeholders (`{app}`, `{name}`),
  so translators may reorder them.
- Date and time formats are translatable GLib/strftime patterns (below).
- Strings meant for developers (log messages, D-Bus error names and
  texts, command-line errors of `helix-extensions`) are not translated.
- The session's desktop entry (`/usr/share/wayland-sessions/helix.desktop`)
  carries its `Name[xx]` and `Comment[xx]` from the same catalogue.

| `zh_CN` | Chinese (Simplified) | 1 | Monday | 24-hour |

The first weekday and the clock are what glibc's locale data for the
language's main country gives (`de_DE`, `ja_JP`…: `first_weekday` and
whether `t_fmt` uses a 12-hour field); Helix reads them from the locale
(below), so another country's locale (`de_AT`, `en_US`) gives its own.
The shell's clock follows `clock-format` (24-hour by default, as in
GNOME); the login screen falls back to the locale's `t_fmt` when
`clock-format` is unset.

*GNOME does not document this; Helix's choice:* the first catalogues are
machine translations, shipped without waiting for review by native
speakers. Each says so in its header (`Last-Translator: Machine
translation (unreviewed)`), and `TRANSLATING.md` lists each language's
review status; reported mistakes are fixed as they come in.

## Which locale each component follows

| Component | Locale | When it is read |
|---|---|---|
| Shell (panel, menus, notifications, overview, OSDs, dialogs it draws) | The session's environment: `LANGUAGE`, `LC_ALL`, `LC_MESSAGES`/`LC_TIME`/`LC_NUMERIC`…, `LANG`, as the C library combines them | At start; a changed language takes effect at the next login |
| Lock screen | The shell's (it is drawn by the shell) | As the shell |
| Portals' dialogs (`helix-portals`) | The session's environment, as the shell | At start (the portal is started per session) |
| Session (`helix-session`) | The session's environment; reported by `GetLocale` (`contracts/dbus/org.gnome.SessionManager.md`) | At start |
| Login screen (`helix-greeter`) | The system locale: the greeter's environment when it names one (`LANG`, `LC_ALL` or `LC_MESSAGES`), else `/etc/locale.conf`, else `/etc/default/locale` | At start |

The session's environment comes from the login (the user's language as
the display manager or `accountsservice` sets it, or the system
default). *GNOME does not document this; Helix's choice:* the shell does
not watch `org.freedesktop.locale1` or AccountsService for a new
language while running; like GNOME Shell, it uses the new language at
the next login.

## Formats

- **Times**: 12- or 24-hour from `org.gnome.desktop.interface
  clock-format` in the shell and on the lock screen
  (`contracts/gsettings/calendar.md`, "Clock"); the login screen as in
  `components/greeter.md`, "Clock". The patterns themselves
  (`%H:%M`, `%l:%M %p`, with and without seconds) are translatable, so
  a language can write its own separator or AM/PM order; AM/PM come from
  the locale (`%p`).
- **Dates**: translatable patterns for the top bar's date part
  (`%a %b %e`), the lock screen's date (`%A, %B %e`), the calendar's
  headings (the stand-alone month name, `%OB %Y`), the day whose events
  are listed and notification times older than yesterday. Month and
  weekday names are the locale's (`LC_TIME`).
- **The calendar's first weekday** is the locale's (`LC_TIME`
  `first_weekday` and `week-1stday`, as GTK's calendar reads them).
- **Month names**: `%B` is the name as written in a date (genitive in
  Russian, Ukrainian and Polish, "16 ноября"), `%OB` the stand-alone
  name of headings ("Ноябрь 2026"), as glibc and GLib give them;
  Chinese, Japanese and Korean patterns write months as numbers
  (`%Y年%-m月`).
- **Numbers**: percentages through the translatable message `{}%` (so
  a language writes `45 %` or `%45`) with the locale's digits;
  data sizes through GLib's `g_format_size` (decimal units, the locale's
  decimal separator and GLib's own translations); temperatures through
  translatable `{}°C`, `{}°F` and `{} K` (the unit from
  `org.gnome.GWeather4 temperature-unit`, else the locale's measurement
  system, as before).

## Accessibility

Accessible names, descriptions and announcements published on the
accessibility bus (`contracts/dbus/org.a11y.atspi.md`) are the same
translated strings the screen shows; the toolkit name reported to
assistive technologies stays `Helix`.

## Chinese, Japanese and Korean text

- **Fonts**: characters the interface font lacks are drawn with the
  font fontconfig picks for them (`sans-serif:charset=…`), using the face
  of a font collection that fontconfig chooses for the locale's language
  (Noto Sans CJK SC in `zh_CN`, JP in `ja`); a font already loaded for
  other characters is reused when it has the character. The packages
  suggest the Noto CJK fonts (`fonts-noto-cjk` on Debian and Ubuntu).
- **Line breaking** (wrapped text: notification bodies, dialogs, the
  lock screen and login screen messages): lines break at spaces and
  between the characters of scripts written without spaces (Han
  ideographs, kana, CJK punctuation and full-width forms), except that a
  line never starts with closing punctuation, small kana or the
  prolonged sound mark and never ends with an opening bracket or quote
  (the kinsoku rules of UAX #14). Korean breaks at its spaces. A word
  wider than the line is broken between its characters rather than cut
  off.
- **Widths** (all languages): window and app menus grow to fit their
  longest entry (up to twice their usual width), and so does the
  notification list's Clear button; other labels that do not fit are
  shortened with an ellipsis.

## Right-to-left languages

*GNOME does not document this; Helix's choice:* the direction follows the
translation, as GTK's does: a right-to-left language's catalogue
translates the message `left-to-right` (context `text direction`) as
`right-to-left`. (`HELIX_TEXT_DIRECTION=rtl|ltr` overrides it, for
testing.) Then:

- **Text** is drawn in visual order by the Unicode Bidirectional
  Algorithm (UAX #9): each line takes the direction of its first strong
  letter (the interface's direction when it has none), right-to-left
  runs read right to left with paired brackets mirrored, and numbers and
  Latin words inside them keep their own order. Wrapped text (notification
  bodies) lays its words out in each line's direction. Characters the
  system font lacks are drawn with the font fontconfig picks for them.
- **Mirrored layouts**: the shell's own surfaces are drawn as the mirror
  image of their left-to-right layout, with text and pictures kept
  readable: the panel (activities and workspaces at the right, the
  system status at the left), quick settings, menus and tooltips, the
  app and window switchers, the app grid and search, the dock, the
  notification banners and list with the calendar, OSDs, the end-session
  and other dialogs, prompts, the extensions dialog, the panel editor,
  the break screen and the lock screen; and the login screen. Sliders
  fill from the right; arrows drawn as shapes point the other way.
  Clicks and accessibility actions on them land on the mirrored
  controls.
- **Not mirrored**: surfaces that show the screen's own geometry (the
  overview's window layout, the screenshot and screen recording UI, the
  workspace switcher popup, desktop icons) and the on-screen keyboard,
  whose layout is the keyboard's.
- Times keep their digit order (`14:05`).

## Testing

`tools/i18n/make-pseudo.sh` builds an `en@pseudo` catalogue that accents
and brackets every message, which shows untranslated text and tight
layouts; `tools/i18n/make-test-rtl.sh` builds a right-to-left test
catalogue for `he` (each message written letter for letter in Hebrew
script, not a translation). Neither is shipped. The shell's, lock
screen's and login screen's render galleries draw in the locale of
their environment (`TRANSLATING.md`, "Testing layouts").

## Not done yet

- The shipped catalogues are machine translations that no native
  speaker has reviewed yet (see "Shipped languages").
- Full UAX #14 line breaking (Thai and other scripts that break by
  dictionary, hyphenation) is not done: only spaces and the CJK rules
  above break lines.
- Scripts that need shaping (Arabic, the Indic scripts) are drawn
  letter by letter, without joining or reordering of marks: the text
  renderer has no shaping engine. Hebrew and other scripts without
  shaping are drawn correctly.
- On mirrored surfaces the bounds published on the accessibility bus are
  those of the left-to-right layout (actions still land right); the
  arrow keys move focus in the left-to-right direction; directional icons
  (media skip, "go next") are not swapped for their right-to-left
  variants; text fields edit right-to-left text with the caret placed as
  in left-to-right text.
- Names that come from data are shown as they come: network and device
  names, app names (from their desktop entries' localized names where
  the app index provides them), world clock city names from their
  settings, and PAM's prompts on the login screen (translated by PAM in
  greetd's locale).
